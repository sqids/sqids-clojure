# Repository Guidelines

## Layout and contracts

- Runtime and public API live in `src/org/sqids/clojure.cljc`. Keep implementation
  helpers private. Behavior tests live in `test/org/sqids/clojure_test.cljc`;
  the differential parity harness remains under `test/org/sqids/clojure/`.
- `sqids` validates an options map once and returns a non-associative `deftype`
  instance directly. `encode` and `decode` require that instance and reject raw
  options or wrapper maps. Keep options separately and reconstruct to change
  settings; the instance's fields are implementation details.
- Keep runtime code dependency-free and focused on the algorithm. Test generators
  and reference implementations belong under `test/`, benchmarks under `dev/`.
- Use ordinary return values and `ex-info` for errors. Do not add result-envelope
  frameworks, metadata caches, or automatic configuration compilation on calls.
- Prefer simple Clojure. Use private mutable buffers only when measurement shows
  a benefit; never mutate shared configuration or caller-owned values.
- Preserve arbitrary JVM integers and the ClojureScript safe-integer boundary.
- `resources/org/sqids/clojure/blocklist.json` is generated by
  `bin/update-blocklist`. Missing bundled data must fail clearly.

## Verification

- `bin/kaocha`: JVM and ClojureScript tests. `tests.edn` owns suite/report settings.
- Test public behavior with known vectors, deterministic properties, invalid
  inputs, and relevant regressions. Avoid tests that only mirror implementation.
- Coverage includes algorithm loops, with a 90% minimum. Do not hide executable
  code from coverage or contort algorithms just to reach 100%.
- `SQIDS_SPEC_DIR=/path/to/sqids-spec bin/parity`: compare both runtimes with the
  upstream TypeScript implementation in the shared safe-integer domain. Compile
  the Node runner with advanced optimization and inferred externs.
- `bin/benchmark`: allocation budgets for ordinary, multi-digit, and bigint
  inputs, plus many-number allocation scaling.
- `bin/benchmark-node`: advanced-compiled Node timings with default and empty
  blocklists. Compare latency on the same runtime/hardware; do not gate CI on
  noisy timings.
- `pre-commit run --all-files`: formatting, lint, shell checks, and tests.
  CI runs hooks with `SKIP=kaocha-test`, then runs the tests separately.
- Run formatting before tests; changing source during coverage invalidates reports.

## Maintenance

- Follow `.cljstyle` and `.clj-kondo/config.edn`; document public contracts and
  non-obvious helpers. Keep scripts executable and dependencies pinned.
- Keep README examples, CHANGELOG, and CI commands synchronized with behavior.
- Select stable dependency releases at least 14 days old; document security-fix
  exceptions with upstream evidence. Keep npm and Python transitive pins, CI
  tool versions, and action SHAs synchronized. Preserve the npm release-age
  gate and Python constraints when updating or running hooks.
- Prefer focused changes. Describe the problem, resulting behavior, and validation
  in PRs, with short imperative commit subjects.
